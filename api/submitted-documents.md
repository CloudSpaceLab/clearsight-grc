# Submitted document API

Both endpoints are authenticated reads. Tenant and principal come from verified identity. A wildcard identity must select one legal entity; a regular identity always uses its verified entity.

`GET /api/v1/forms/documents` accepts `file_kind` (`PDF`, `IMAGE`, `WORD`, `SPREADSHEET`, `OTHER`, or omitted), `query` (literal filename substring), `form_template_id`, `relationship_id`, `response_revision_id`, `current_only` (default true), `cursor`, and `limit` (1–100, default 25). It returns `{items: DocumentOccurrence[], next_cursor?: string}`. To view an old response use its exact revision and `current_only=false`.

Each occurrence contains `id`, `artifact_id`, `request_id`, `submission_id`, `field_id`, optional `response_revision_id`, `distribution_id`, `relationship_id`, `assessment_id`, `work_request_id`, `form_template_id`, `form_template_version`, `form_title`, `field_label`, `file_name`, `media_type`, `file_kind`, `size_bytes`, `sha256`, `artifact_status`, `uploaded_at`, optional `uploaded_by`, `submitted_at`, optional `submitted_by`, optional `expires_on`, `current`, and optional `review` (`id`, `status`, `reviewed_by`, `reviewed_at`, `source: VENDOR_ASSESSMENT`). Missing attribution is unknown; submitter identity must not be presented as uploader identity. These are principal IDs, not inferred names or email addresses. The occurrence ID is opaque to clients.

`review.reviewed_at` is omitted when no review has been performed; actual decision timestamps remain present. For assessment and vendor-work captures, `current` follows the latest submitted capture affecting that field. Sending a successor request does not retire prior files. A submitted replacement retires affected fields, including requested fields whose replacement answer is empty, while unrelated carried-forward fields remain current. Business rejection and expiry do not themselves change this classification.

`GET /api/v1/forms/documents/{submission_id}/{field_id}/{artifact_id}/content` accepts optional `response_revision_id` and `download=true`. It repeats exact scoped membership authorization and requires AVAILABLE bytes whose complete digest and size match the manifest before delivery. Historical business rejection or expiry does not alter security availability. The upload request can differ from the submission request for another contributor; its resolution remains internal. Clients must percent-encode every path segment and use authenticated same-origin delivery.

`GET /api/v1/forms/responses/{revision_id}` adds `submission_id`, `answers` (`field_id`, `label`, `type`, `value`), `documents` (first 100 exact occurrences) and `documents_next_cursor`. All answers come from that exact immutable submission and form snapshot. Answer content is returned only for supported, authorized subjects whose request scope matches the response. Existing response metadata and revision DTOs are retained.

For assessment and vendor-work origins, answer reads additionally require the exact stored workflow capture link, form revision, and owning workflow read authority, including the work's Program or Matter target visibility. This applies to scalar-only submissions; an empty document inventory is never evidence of permission to read answers. Missing workflow authority denies the response detail before any answers are returned.

## Vendor collection reconciliation

Occurrences also expose `submission_channel`. Reconciliation accepts only `MAGIC_LINK` vendor submissions, available current evidence in the same vendor relationship, and files meeting the requested field's file constraints.

- `POST /api/v1/vendor-assessments/{id}/prepare-request`: `{expected_version, audience, deadline}` returns `{assessment, request, state: "PREPARED"}` without issuing an invitation. The existing send endpoint accepts an empty audience to resume the stored protected recipient and its deadline.
- `GET /api/v1/vendor-assessments/{id}/collection`: returns `assessment_id`, `assessment_version`, optional `request_id`/`request_version`, `prepared`, `deadline`, masked `audience_hint`, `can_reconcile`, `can_start_review`, `observed_at`, `fields`, `vendor_pending_count`, `bank_pending_count`, and `accepted_document_count`.
- `POST /api/v1/vendor-assessments/{id}/collection/{field_id}/reconcile`: `{expected_version, request_id, expected_request_version, source_submission_id, source_field_id, source_artifact_id, source_response_revision_id?, rationale}` returns `{collection, receipt}`. Current reviewer authority and exact source read access are re-evaluated before the atomic write. Version conflicts require refreshing the checklist before retrying.

Each checklist field contains `field_id`, `label`, `type`, `required`, `collection_state` (`MISSING`, `RECEIVED`, `REUSED`, `NOT_REQUIRED`, `CONDITION_UNKNOWN`), `vendor_action_required`, `bank_review_state` (`PENDING`, `VALIDATED`, `REJECTED`, `NOT_REQUIRED`), and optional `resolution`. Unanswered conditions remain unknown. Scalar answers require no separate bank field acceptance and never increase the accepted document count.

A resolution records `id`, `version`, optional `supersedes_id`, the submitted `source` occurrence, original `source_artifact_request_id`, document metadata, `reconciled_by`, `reconciled_at`, `rationale`, independent `bank_review_state`, and optional review actor/time. Reconciliation clears collection only; explicit validation uses the existing document review endpoint. That endpoint accepts `field_id` and requires it when an artifact satisfies more than one requirement. No answer or vendor submission is fabricated. All-held assessments may enter `UNDER_REVIEW` with `collection_completed_at` while `submission_id` and `submitted_at` remain absent.

Rejection, expiry, source replacement and unavailable bytes invalidate current fulfillment; the original decision remains reconstructable. Respondent requests expose only `collection_received`, never the receipt or bank review metadata. Protected assessment document previews require the exact receipt source and repeat source inventory authorization. Unknown identity, scope mismatch, unavailable authority and inaccessible sources fail closed.

The inventory and content endpoints expose no storage key, access selector, session token, draft answer or invented review decision. These read endpoints do not authorize accept/reject, replacement or disposal commands; assessment workflow endpoints enforce their own reviewer authority. The read contract and deployment limits are described in [submitted-document architecture](../docs/architecture/submitted-document-reads.md).

In validated non-production demo mode only, an occurrence may additionally contain `demo_preview_available: true` for an exact shipped fictional sample that remains `STORED_UNSCANNED`. The list service recomputes this optional capability; client query/body flags cannot grant it. The same content endpoint re-authorizes the occurrence and independently verifies the original stored sample bytes before preview or download. This exception does not mark the file AVAILABLE, record a malware scan, or enable evidence acceptance. Clients show **Demo check complete** and **No antivirus scan was performed** before sample content/actions. Unknown, changed, quarantined or deleted files remain blocked even if a client sends a capability flag.
