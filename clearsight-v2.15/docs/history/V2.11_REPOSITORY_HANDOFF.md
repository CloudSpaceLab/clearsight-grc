# V2.11 implementation handoff

## Deliverables

- `clearsight-v2-demo.html`: standalone interactive application, starting at Work.
- `assets/`: shared source modules and styles, including assessment tracking, vendor onboarding, unified Documents and response reporting.
- 75 HTML entry points for direct module access.
- `docs/`: source mappings, workflow contracts, architecture, audit and validation.
- `tests/`: actual-source Node suites plus explicitly historical browser artifacts.
- `build.py` and `verify_reference.py`: HTML build and untouched-release integrity verification.

The ZIP updates the existing interactive design package. No production repository has been merged or deployed.

## Integrate the interaction layer

Load the five V2.11 adapters in the build's order after the established domain modules. Keep generic modal submit/action dispatch promise-aware. Preserve the distinction between false (a staged, unapplied next step) and successful completion, and preserve its dirty-state guard. Do not remove form controls from FormData merely to lock a pending operation; the implementation uses an inert body.

Use exact route/query context for work, correction and report drill navigation. Replace native hash/history/dialog mechanisms with the production router's corresponding blocking/focus primitives, then observe them in real browsers. Preserve the existing domain commands behind these interaction improvements. The audit and domain UX notes map each changed flow and its retained constraints.

## Integrate identity and workflow together

Persist the target, respondent, coordinator, actual submitting actor, assigned reviewer and actual decision actor as separate fields. Bind submits/reviews to the authenticated session on the server. Enforce current scope, explicit denies, reviewer eligibility, source version and self-review separation at command boundaries. Per-person assignments must not share mutable response storage simply because their organizational target matches.

Store submitted episodes and review events immutably. Preserve accepted conclusions while a correction is prepared; separately compute whether the latest response is current enough for activation. Do not infer legacy people, times, reviews or source document versions. Questionnaire acceptance and requirement decisions are separate commands.

Retain one document store with immutable versions and contextual review references. A document's uploader need not be the person submitting it to an assessment. `d210Review` and the legacy `jEvidenceDecision` adapter are now asynchronous; await byte verification before recording acceptance. In production this verification and decision must use transactional/current-version guards against concurrent change.

Vendor intake must create real work through the assessment/document services after reviewed plan approval. A dossier checklist is a projection of those authoritative stores. Activation needs accepted current responses, exact approved current documents and reviewed requirement conclusions. Do not bypass these checks in legacy vendor/setup/portal routes.

## Reports, work and migration

Work and Inbox should point to exact assignments, submitted episodes, document versions and dossier stages. Preserve the distinction between reading, acknowledging and resolving. External supplier obligations need an internal accountable coordinator; real invitations and delivery require separate integration.

New report snapshots capture response accountability; existing packs must not acquire live annexes. Avoid changing compliance denominators when adding response completeness/review metrics. Keep prior loss contracts: original currencies, explicit dates, verified cash, retained corrections and closed-loss inclusion.

The V2.11 local-state key accepts V2.10 and earlier fallback. Treat that as a demonstration migration, not a database migration procedure. Document the production schema/backfill plan with explicit unknown provenance.
