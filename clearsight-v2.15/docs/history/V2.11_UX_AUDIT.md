# V2.11 workflow interaction review

## Scope and design decisions

The review covered the delivered workflow families from their ordinary entry points, including preparation, save/resume, validation, review, correction, source navigation and reporting. The main issue was not missing screen count: working source records and commands were often exposed through ambiguous actions, long records or late validation. Users had to infer who should act, where the missing information lived and which pending item actually blocked progress.

The implementation puts those answers beside the work. It keeps domain validators and decisions authoritative, uses the existing draft stores and avoids adding an alternative workflow repository. It does not use a visual completion percentage as a substitute for source readiness or approval.

## Coverage matrix

| Work and ordinary actions | Mixed owners and unsorted due work; broad destinations | Person/lane/type/search filters in the route, deadline ordering, specific action labels, direct work-item pages | Completing an ordinary action does not approve its source. |
| Inbox and follow-ups | Newest information hides unresolved due work; follow-up returns to broad queue | Action-priority and due filters, validated direct source action, exact follow-up destination | Read, acknowledge, snooze, archive and source resolution remain distinct. |
| Framework adoption | Publication ends before the operator sees named response assignment work | Publish handoff opens named assignments; final-check links return to the relevant step | Canonical requirements and applicability remain pinned. |
| Forms and named assessments | Respondent/reviewer see similar generic actions; long errors require searching | State/actor-derived next action, remaining-item navigation, exact grid/Document focus, changed-answer review | Actual respondent/reviewer identity, independence, source versions and submitted history remain enforced. |
| Documents and contextual reviews | Broad pending queue, generic document link, difficult return to assessment | My review queue, exact version/context, return-to-response and next-review links | One file/version store; file approval, response review and requirement conclusions remain separate. |
| Vendor intake and diligence | Generic activation guidance sends all blockers to assessments | Intake section correction and blocker-specific questionnaire/document/approval/conclusion handoffs | All mandatory readiness gates must pass before independent activation. |
| KRI preparation and review | 51 expanded observations; missing and unavailable answers are easy to confuse | Compact attention register, separate answer categories, exact-question jumps, live readiness | Unknown, zero, N/A and measured values remain distinct; approved returns remain immutable. |

## Common interaction contract

Every meaningful action has an explicit source and outcome. Error links move to the affected field rather than replacing a record. Pending modal operations are visible and cannot be double-submitted or edited underneath a captured asynchronous save. Errors retain input. Proposed-but-unapplied comparisons remain unsaved. Modal dismissal and internal history navigation give Keep editing/Discard choices when necessary.

The shared helpers are `ui211Route`, `ui211Focus`, `ui211Issues` and `ui211Next`. Domain adapters use them where they remove real friction; they do not add an explanatory panel to every page. Canonical list memory remains in use, and generic clear-filter controls avoid hidden search state. Working headers, constrained action groups and responsive review spacing support longer enterprise tasks.

## Validation and remaining observation work

The actual-source suites cover consequential commands, identity/scope/version integrity, draft preservation, source-specific routing, effective/proposed comparisons and captured reports. The route checks inspect every built entry point and selected interaction variants for registered actions, valid destination names and non-placeholder output.

These checks substitute the browser shell. Layout at actual viewport sizes, keyboard/screen-reader behavior, native dialog focus/history behavior, browser inert support, file storage/download and print still require observation in an allowed browser. No screenshots or browser usability certification are claimed for V2.11.
