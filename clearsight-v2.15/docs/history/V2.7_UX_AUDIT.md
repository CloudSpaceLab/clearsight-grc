# V2.7 — Practical bank-workflow audit

13 November 2026 · Changes to the local UI reference, not the production repository

## Method

Reviewed the actual V2.6 sources, bank workflows and existing tests. Probed wrong IDs/targets, descendant scopes, work routing, readings, exact document versions and asynchronous commits. Modified the shared sources, not screenshots. Retained domain tests and added `tests/audit_copilot_checks.py`. The before-probe is `tests/audit-before.json`; it is partial diagnostic evidence, not a complete audit catalogue.

## Defects and corrections

| Problem | Bank-use consequence | Correction |
|---|---|---|
| An unknown program ID could fall back to the first program; an invalid target could become the first target. | A reviewer could assess a different bank service than the source link named. | Explicit bad IDs, targets, assignments and versions fail closed. No substitute record. |
| Removed or inconsistent stored organizational IDs could clear to All. | A report could silently widen beyond its intended location. | Block the data view until a valid scope or explicit clear-all is chosen. |
| Domain views blocked an out-of-scope record without consistently signalling contextual components. | Copilot or attachment components could redisplay data the primary page hid. | Shared blocked state, exact vendor-assignment scope and suppressed contextual components. This is UX correctness, not server authorization. |
| New actions lacked accountable scope; indicator-breach actions could lose scope through an indirect reference. | Work disappeared from branch queues and reports. | Explicit owner/location on new actions; typed related record; indicator actions inherit their linked risk scope. |
| Insight actions could open a generic task editor for evidence/review work. | Users reached the wrong decision controls. | Normalize through the shared Work projection and open the canonical source review. Include final sign-off in review classification. |
| Indicator creation offered risks outside the current branch. | Users accidentally created cross-location relationships. | Scope both choices and final validation. A location without a risk explains the prerequisite. |
| Backdated observations replaced current readings. | A historical capture changed the current dashboard. | Reject older current-value updates. A dedicated historical-ingestion path is still production work. |
| Missing/invalid evidence dates and future/malformed indicator timestamps could imply usable current data. | Unreliable freshness and assurance status. | Explicit Unknown / Not yet current states; zero remains a valid numeric value. |
| Single-file answers could accept a batch, and uploads sent users away from the assessment. | Answers were overwritten; respondents lost their context. | One-file destinations reject a batch. Save returns to the original source. Grid fields resolve the response's original/pinned definition. |
| User identity could change while file storage or approval verification was awaiting completion. | The resulting attribution could differ from the person who started the action. | Pin/recheck the actor and record state after asynchronous work; fail without creating an accepted decision. |
| Tablet header actions overflowed when a contextual action was added. | Buttons became inaccessible or displaced the page. | Wrapping action groups on both shared and full-record headers; no second scope bar. |
| CSV formula text and numeric negatives shared formatting behaviour. | Exports could either trigger formula interpretation or damage numeric semantics. | Numeric values remain numbers; dangerous text prefixes are neutralized. |
| Timestamps and actor labels varied across views. | Review history became harder to interpret. | WAT timestamp presentation and the selected, explicitly labelled demo actor. |

## Copilot interaction decisions

The assistant opens inside the current workspace; it does not replace record pages or become a permanent right flyout. Three tasks are visible. Sources are linked beside desktop answers and collapsed on smaller displays. Untrusted labels are escaped. Original file contents and Restricted document metadata are not included in its context.

A proposed action has a visible source basis. The existing action form still requires the accountable location, owner and date. Cancel has no effect; confirm creates an ordinary work record with proposal provenance. Recomputing the context hash rejects a stale proposal. No copilot action changes risk ratings, approvals or requirement evaluations.

Context is page-specific: form design versus response readiness, unit/month KRI versus bank consolidation, selected document version versus explorer filters, and published report snapshot versus live report. Navigation scope changes never reassign a submitted assessment.

## Deliberately not claimed

This is not a complete production audit. The demo still lacks server permissions, concurrent users, live collection, a configurable full bank KRI catalogue, full bulk ingestion, document lifecycle/legal-hold controls and real signing. Remaining limits are documented rather than covered with fake UI success.

Scope filters are not permissions. A production implementation must apply authenticated tenant/actor authorization before resolving the same read models. The preserved October references and production domain contracts must not be replaced by browser-local state.
