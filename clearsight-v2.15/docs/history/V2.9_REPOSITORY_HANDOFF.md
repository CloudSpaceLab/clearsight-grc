# V2.9 implementation handoff

## Deliverables

- `clearsight-v2-demo.html`: standalone interactive application, starting at Loss register.
- `assets/`: shared source modules and styles.
- 67 HTML entry points: direct module access with shared assets.
- `docs/`: source mappings, workflow decisions, architecture, audit and tests.
- `tests/`: actual-source Node suites and retained historical browser suites/results.
- `build.py` and `verify_reference.py`: reproducible HTML build and untouched-release integrity check.

The ZIP updates the existing design package. No production repository has been merged or deployed.

## Integration order

Adopt the fields and state transitions before connecting UI writes. Implement authenticated identity and source-scoped retrieval, permission checks, transaction/version guards, durable snapshots and money validation in the service layer. Move document-version ownership and access to secure storage. Connect financial reconciliation, recipient notifications and background escalation separately; none are live integrations in this package.

Keep account/loss/risk classifications distinct. Preserve occurrence, recognition, reporting period and received-cash windows. Never infer verified cash from a recovery narrative or combine currencies without an explicit approved FX basis. Closed losses retain financial impact. Corrective-action completion does not revise an accepted risk/return/loss conclusion.

Migrate existing data with provenance. Retain legacy unknown fields for enrichment; avoid fabricated dates or review receipts. Publish new board snapshots from the selected cohort and keep existing packs unchanged. Source mappings and CSV staging provide a practical path for controlled workbook migration.

## Verification before production use

The shipped test report distinguishes actual-source checks from browser validation. Run the suites in the target implementation and add integration checks at the service/transaction boundary. Complete real-browser layout, keyboard/screen-reader, narrow-screen, file-storage, download and print checks in an allowed browser environment. Historical V2.7 screenshots are not evidence of the V2.9 layout.

This handoff does not claim a production security boundary, live scheduler, email delivery, real financial ledger or enterprise master-data integration.
