# Implementation handoff — V2.13

## Deliverable

This folder continues the existing ClearSight interactive reference. `clearsight-v2-demo.html` is the self-contained application; `assets/` contains readable source modules. `build.py` rebuilds the standalone and 80 module entry points. `MANIFEST.json` and `verify_reference.py` verify the untouched release.

The release adds premium presentation to the established V2.12 workflows. Canonical records, named response/review history, permissions, organization scope, financial semantics and frozen reporting remain authoritative.

## New adapters

| Module | Responsibility |
| --- | --- |
| `premium-foundation.js/.css` | Shared semantic tokens, chrome, controls, tables, dialog styling and persisted display preferences without page rebuild |
| `premium-workspaces.js/.css` | Responsibility/work queues, Inbox action placement, named identity, role/access comparisons and escalation presentation |
| `premium-forms.js/.css` | Assessment/review, KRI/loss, vendor and document reading/capture hierarchy; one constant recipient-only stylesheet |
| `premium-reporting.js/.css` | Report/dashboard wrappers, analytical hierarchy, chart readability, captured-pack presentation and reversible print disclosures |

They load in this order after `external-assessments` and before bootstrap. They consume the existing semantic palette and source commands. `S.theme` and `S.displayPreferences.density` are the only display settings; they never authorize an action.

The V2.12 source state is read as a migration fallback before older supported keys. No seed role was widened for this release. All module/route output is rebuilt from shared source.

## Adoption

Bind the new visual tokens to the production design system, then adopt the shared shell and controls before the workflow-specific refinements. Keep the current canonical source commands behind their existing role/scope guards. Integrate the exact same field names, IDs, source URLs, version references and independent-review transitions.

Apply display changes in place. Avoid rerendering an active assessment, loss or review form merely because density/theme changed. Keep compact spacing a desktop preference and verify touch targets independently of the selected density.

Report styling must not recompute a published pack. The presentation wrapper preserves the existing body; printing expands/restores only analytical DOM disclosures. Recipient styling must stay within the separate minimized file, without importing the internal bundle or state.

## Verification

Use `tests/validation-summary.json` as the authoritative inventory. The V2.13 source checks cover appearance persistence/draft preservation, queue decoration, exact recipient isolation, report content preservation and print-state restoration in addition to the retained domain suites. The route checker is `tests/routes_v213_checks.js`.

Read `docs/TEST_REPORT.md` before treating any result as browser acceptance. The environment could not validate computed layout, keyboard/screen-reader interaction, native file storage/downloads or print pagination. Review supported browsers at 320/390/768/1024/1440 px, light/dark, comfortable/compact, and text zoom. Check long names, long instructions, empty/denied states, open dialogs and original document worksheets.

## Production integration boundary

The package still uses synthetic local records. Authenticated server commands must bind actual identity and tenant, enforce exact scope and independence, protect audit history and implement concurrency. The external portal must enforce recipient assignment, expiry/revocation and attachment processing. Documents require approved durable storage and safe preview conversion. Notification delivery and schedules require server implementation. The visual increment does not imply those services are deployed.
