# ClearSight V2.9 architecture

## Runtime and build

The package is dependency-free HTML, CSS and JavaScript with synthetic state. `build.py` generates 67 entry points and one fully inlined `clearsight-v2-demo.html`, now starting at `losses`. `assets/app.js` restores schema-3 state using a V2.9 key, with V2.8 and earlier fallback. No live data, email or scheduler connection is implied.

Load order: seed → app → forms → experience → journeys → insights → records → document store → documents → usability → Copilot → KRI schema/branch KRI → governance → inbox → board reports → loss schema/register → workflow completion → flow polish → loss reporting → bootstrap. Shared functions are intentionally adapted in this order. `build.py` and the actual-source harness contain the authoritative ordered lists.

## New modules

| Module | Responsibility |
| --- | --- |
| `loss-schema` | Exact source-field mapping, vocabulary and financial distinctions. |
| `loss-register` | Drafts, source context, independent financial review, corrections, receipt verification/reversal, closure/reopening, CSV import and legacy loss adapters. |
| `workflow-completion` | Control editor/tests, durable RCSA drafts/provenance, vendor lifecycle reviews, risk context editor and correction queues. |
| `flow-polish` | Scoped form/assessment corrections, evidence refresh, approval preparation, privacy reopening, verified Work closure and exact Inbox resolution. |
| `loss-reporting` | Date/currency-specific cohorts, concentration/lag/aging/cash insights, captured board annex and matching Copilot contexts. |

## Loss state and money

`S.losses` stays canonical for submitted and accepted event records. `S.lossRegister.drafts` holds preparer work and staged imports. `pendingRevision` holds a correction while accepted fields remain unchanged. `versions`, submission snapshots, decision receipts and event history retain provenance. Imported source columns remain attached to resulting events.

`lossFinanciallyIncluded` admits Accepted and Closed events. Receipt helpers distinguish gross received cash, verified balances and approved reversals by effective date. Values are safe integers in original-currency minor units. Existing NGN dashboard readers and risk monetary cards use reviewed NGN cohorts; dedicated loss reports select one currency. No automatic FX conversion is performed.

Occurrence, recognition and explicit reporting period are separate dimensions. Reporting quarter/year are derived. Near misses have no financial recognition date. Legacy data is not assigned invented financial dates.

## Decisions, work and notifications

Preparation and review remain distinct. Command boundaries recheck current scope, actor, approval authority, source membership, version and evidence availability as applicable. Exact-source decisions emit notifications; returned work is actionable until its linked replacement submission. Read, acknowledgement, archive and source resolution remain different states.

Corrective actions do not change source ratings, approved returns or accepted losses. Loss/KRI actions require independent verification. Reopening retains completion episodes. Control definition changes invalidate current effectiveness without deleting prior conclusions. Vendor state transitions require the appropriate review and current gates.

## Frozen reports

Board packs capture source definitions, figures, context, narrative and chart models. V2.9 adds `operationalLoss` to newly captured snapshots. Existing packs are not backfilled with live financial data. Copilot respects visible live filters or frozen snapshot context.

## Production integration boundary

Local persistence and synthetic identity switches are a design reference. Read views retain selected organizational-scope behavior; browser state is not authenticated confidentiality or authorization. Production needs authenticated row-level retrieval, server-side permissions, immutable decision storage, atomic/concurrent writes, document access, real notifications and scheduled escalation. These are integration requirements, not controls provided by this HTML package.

Actual-source model/routing tests use a minimal DOM shell. Real-browser layout, persistence, downloads and print remain unverified in this environment. Historical V2.8 architecture is in `history/V2.8_ARCHITECTURE.md`.
