# V2.9 data and workflow review

## Source-driven decisions

The supplied LOSS DATA BASE workbook separates account classification, loss group, transaction particulars, organizational dimensions, occurrence/recognition/reporting dates, root cause and recovery information. V2.9 represents these separately and derives redundant period labels from a single explicit period. The complete mapping is in `LOSS_REGISTER_V29.md` and `LOSS_DATABASE_MAPPING.json`.

Repeated transactions across month labels are duplicate candidates. Quarter inconsistencies are preview warnings, not silent changes to the original source. Recovery narrative without a received amount/reference cannot reduce net. Reference workbook personal transaction details are not distributed in the demo.

## Integrity controls exercised

| Risk | Current behavior |
| --- | --- |
| Submitted/corrected values distort reports | Accepted facts remain until independent review; new submissions stay excluded. |
| Foreign currencies treated as NGN | Legacy totals use accepted NGN; event tables and operational reports state original currency. |
| Reporting month inferred from recognition | Explicit period and discrepancy explanation; source labels remain provenance. |
| Duplicate rows across reporting months | Cross-period fingerprints; distinct-reference explanation; draft-only import. |
| Narrative recovery treated as cash | Received and expected amounts are separate; verification controls net loss. |
| Missing evidence partly changes money | Evidence is preflighted before loss acceptance/receipt verification; rejection remains possible. |
| Closure removes a residual loss | Closed records remain included; residual treatment is explicit. |
| Correction collides with closure | Commit guards prevent simultaneous financial and closure decisions. |
| Review authority changes | Source/destination scope and current permissions are rechecked. |
| Control/risk basis changes after submission | Frozen source/version checks prevent stale conclusions. |
| Returned work disappears | Owner Work rows, actionable alerts and exact replacement links remain until resubmission. |
| Action correction loses prior accountability | Completion/verification episodes and owner/due/source history remain preserved. |

## Model compatibility

Older loss setups are redirected to the current reviewed capture. Existing synthetic gross/received amounts remain unchanged on migration; missing recognition and classification facts remain unknown. A missing risk mapping is valid; a nonempty orphan link is still flagged. Reporting helpers retain the existing day-offset contract, including 30/90/365-day trend comparisons.

Published old/new report snapshots stay unchanged after live edits. Recognition cohorts exclude near misses as not applicable. Copilot matches actual currency/date/search/state filters and does not substitute the generic dashboard for a loss report.

## Remaining integration work

This package is not a production backend. CSV, local state, document references and demo identities demonstrate UI contracts. Native XLSX ingestion, authenticated row-level data retrieval, financial-system reconciliation, secure object storage, transactional/concurrent writes, real delivery and scheduled monitoring must be implemented in the production system. Real-browser visual and storage verification remains a handoff gate because browser execution was blocked here.
