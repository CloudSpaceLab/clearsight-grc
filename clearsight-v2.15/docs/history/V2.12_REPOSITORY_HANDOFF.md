# Implementation handoff — V2.12

## Deliverable

This folder is a complete dependency-free interactive reference. `clearsight-v2-demo.html` is the standalone artifact; `assets/` contains the readable source modules. `build.py` regenerates the standalone and module entry points. `MANIFEST.json` and `verify_reference.py` validate an untouched release.

The release continues the existing UI package. It does not contain or deploy a production backend. The new UI is wired to the same canonical local domain commands, with additional scope and acting-identity guards.

## New modules and ownership

| Module | Responsibility |
| --- | --- |
| `role-experience.js/.css` | Personal entry, active responsibility lenses, My access, scoped navigation/search/actions and covered actual-actor command guards |
| `scoped-analytics.js/.css` | Canonical organization/URL context, report cohort access, contextual assurance, saved views and captured board scope |
| `document-management.js/.css` | Scoped document queries, preview/compare, lifecycle details, guarded upload/read/export/archive and external byte capture |
| `external-assessments.js/.css` | Request lifecycle, minimized recipient package, response inspection/import and canonical reviewed-response handoff |

Load these after the V2.11 adapters, in the order shown, before bootstrap. The role API is available to scoped analytics and Documents; external assessments consumes all three. Existing document upload has narrow pre-storage and precommit permission/context checks. Canonical publication now pins program scope directly, and optional-grid validation inspects human columns without deleting or misclassifying technical observations. No competing organization, document or assessment response store was introduced.

## Production workstreams

1. Map the interaction commands to authenticated server operations. Bind the actual actor and tenant on the server, then enforce exact scope, direct restrictions, independence and optimistic concurrency.
2. Implement the external request as an authenticated recipient portal. Use minimally scoped assignment access, server expiry/revocation, response provenance, attachment scanning and a durable review queue. Do not serve the full internal bundle behind a hidden sidebar or bearer query string.
3. Move Documents metadata/bytes to approved durable storage. Preserve exact-version links and receipts. Apply scanning, retention and access policy before preview/download; use a controlled converter where full fidelity Office preview is required.
4. Define reporting populations and cross-branch organizational functions in the domain model. Preserve selected source boundaries, financial currency/date semantics and captured pack facts across server queries and exports.
5. Connect actual delivery/scheduling only after recipient resolution, authorization and idempotency are implemented. This release sends no messages or invitations.

## Verification and review

Use the current suite/result inventory in `tests/validation-summary.json`. Historical fixtures are preserved under `tests/history/`; V2.12 fixture adaptations represent real acting identities and scoped authorization rather than the prior permissive shell. State, lineage, finance, source-integrity and snapshot assertions are retained.

Read `docs/TEST_REPORT.md` before treating results as browser acceptance. The current environment could not validate rendered layout or native browser file/dialog behavior. Complete keyboard, screen-reader, desktop/mobile, preview/fallback, storage, save/resume, download and print acceptance in your supported browsers.

## Suggested adoption sequence

Start with the canonical actor/scope contracts and the personal landing page. Integrate report context and read/export separation next. Then integrate document lifecycle and file services, followed by the externally authenticated assessment journey. Keep named response history and requirement decisions separate throughout; importing a form or uploading a file is never an approval.
