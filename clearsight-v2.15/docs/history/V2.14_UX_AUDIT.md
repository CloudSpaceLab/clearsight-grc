# UI/UX consistency audit — V2.14

21 November 2026 · Current source implementation review

## Gaps addressed

| Observed source/UI gap | Implemented response |
| --- | --- |
| The live form editor used different components from the already-refined response form | Explicit cx-editor styling, visible editing boundaries/tools, usable guidance fields and keyboard/touch-accessible table controls. |
| Framework/adoption metadata and applicability became cramped or hidden on phones | Solid previews, wrapped metadata and visible applicability labels with responsive controls. |
| Older risk/control/RCSA details used small source labels and horizontal relationships | Shared reading scale, source/decision separation, responsive relationships, comparison regions and existing matrix/observation values. |
| Loss filters and vendor/KRI catalogs did not match the new capture flows | Matching register hierarchy, wrapping filters and consistent factual summaries. |
| Privacy/case editors and histories retained legacy geometry | Coherent source/capture/review panels, readable chronology and normal-flow narrow/short layouts. |
| Integration checks could be visually mistaken for generic status cards | Preserve actual source statuses, quality and timestamps with clear hierarchy; no invented live connection. |
| Global search could replace an edited dialog | Guard busy operations and use the canonical Keep editing/Discard flow. |
| Phone navigation lacked explicit modal focus/cleanup | Visible close control, expanded state, focus containment, inert/background restoration and desktop cleanup. |
| Search launched from the drawer could retain a hidden focus-return target | Restore the menu opener before search records its return target. |
| Secondary UI surfaces used inconsistent spacing and feedback | Shared search, dialogs, validation, next actions, empty states and contextual Copilot presentation. |
| Settings administration shortcuts appeared before the page title | Move the existing H1/tabs first, followed by display preferences and administration content. |
| Document folder/filter/approval catalogs lagged behind the preview workspace | Consistent filter/selection/bulk-action hierarchy with original scope, permissions and source routes. |
| Residual Evidence labels presented files as a separate UI concept | Align confirmed public labels with Documents; preserve backing identifiers, source/user text and contextual explanations. |

## Coverage and preservation

All 79 registered routes have an explicit presentation layer in `UI_COVERAGE_V214.json`. Shared theme/density and utility surfaces apply across route families. Domain commands, permissions, financial semantics, history, exact versions and frozen report content remain authoritative.

New JS is limited to route markers, existing-element names, the shared utility interactions and settings node movement. There are no new network resources, data stores, animations or fabricated status measures.

## Acceptance still required

No browser execution was retried after the previously observed restriction. Actual-source checks establish preservation and control-state logic, not computed layout or native accessibility. Review light/dark, comfortable/compact, phone/tablet/desktop and text zoom, with long labels, open dialogs, editable tables, empty/denied states, drawer/search focus and print pagination. Historical screenshots are not V2.14 evidence.
