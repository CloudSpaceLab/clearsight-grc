## Material scenarios

Tests cover source mapping, exact monetary precision, distinct date bases, optional risk mapping, saved drafts, independent decisions, pending-vs-accepted totals, immutable corrections, precise duplicate references, unknown branch mapping, narrative-vs-received recovery, and original imported provenance.

Independent command review exercises current destination permission, evidence availability before financial mutation, closure/correction conflicts, received/verified/reversed balances, retention of closed losses, legacy setup adapters and preserved action accountability. Reporting checks reconcile 30/90/365-day windows and day offsets, original currencies, gross receipts/reversals, recognition N/A, source classifications, aging/concentration, exports and unchanged published snapshots. Copilot uses the actual visible cohort or captured snapshot.

Other suites test source-frozen control/RCSA conclusions, vendor lifecycle gates, immutable form corrections, evidence supersession, persistent approval preparation, privacy reopening, source-aware Work completion, independent KRI/loss action verification and actionable returned work.

## Running

From the package root, run `python3 build.py`, then each named suite with `node tests/<filename>`. The suite names retaining `v28` validate inherited component contracts against current source; they are intentional regression gates.

The browser environment blocked Chromium process/socket creation and rejected local-file cloud-browser navigation. Those restrictions were not bypassed. Responsive CSS and semantic markup were reviewed in source, but screenshots, rendered mobile overflow, browser file access and print-to-PDF remain unverified. V2.7 browser scripts/results/screenshots are historical only.

`python3 verify_reference.py` verifies the untouched release manifest. Running tests or rebuilding can change result-file hashes; the manifest should then be regenerated intentionally for a new release.
