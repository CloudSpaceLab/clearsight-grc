## Loss recording, review and recovery

The register follows the 18-column **LOSS DATA BASE.xlsx** in the supplied Ops Risk archive. Account classification and bank loss group remain separate. Capture also includes transaction particulars/reference, exact location, regional bank, directorate, original currency, occurrence, discovery, financial recognition, explicit reporting period, root cause, accountable follow-up and recovery narrative.

One reporting period produces the month, month number, quarter and year. It is not inferred from occurrence or recognition. Differences from recognition month need an explanation. A risk link is optional, so missing taxonomy mapping does not prevent a genuine loss from being recorded.

1. **Capture and save** a four-step draft.
2. **Submit** to an assigned independent reviewer. Submitted figures stay outside accepted totals.
3. **Accept or return** with a reason and source-version receipt. Returned work stays actionable in Inbox.
4. **Propose corrections** without overwriting accepted facts. Acceptance retains the superseded revision.
5. **Record received recoveries** with amount, date, settlement reference and optional pinned document version. Independent verification changes the recovered balance.
6. **Request a reversal** when a receipt needs correction. The original receipt and its approved effective-date reversal remain in the ledger.
7. **Request closure** with residual-loss and open-action treatment. Closure does not remove the loss from financial reporting. Authorized reopening preserves the closure decision.

Recovery estimates and narrative claims never reduce net loss. NGN, USD, EUR, GBP and ZAR retain separate minor-unit amounts. There is no implicit foreign-exchange conversion. Existing dashboard financial cards retain a reviewed NGN basis; linked event tables show each original currency and review state.

### Worksheet import

Use **Import worksheet** and load a CSV copy of Sheet1 with its original headers. The preview handles quoted CSV, day/month/year or ISO dates and Excel date serials. Unknown branches need explicit organizational mapping. Period conflicts and transactions repeated across reporting periods are flagged.

Duplicate candidates are excluded unless the preparer records a distinct reference and explanation. Selected ready rows become **drafts only**, with original source columns retained. Recovery text does not create receipt amounts. Native XLSX upload is not implemented; save the worksheet as CSV first.

Only source structure and classification vocabulary are distributed. Actual source transaction narratives, customer names and amounts are not included. Legacy synthetic figures stay intact; missing classifications or recognition dates are visibly incomplete rather than invented.

## Reports for directors and boards

Open **Loss insights** from the register or **Reports → Operational losses**. Select occurrence, recognition or reporting-period basis, one original currency and a date window. Event-cohort gross/recovered/unrecovered balances are separate from cash receipts and approved reversals during the window.

Concentration charts cover loss group, account classification, branch, regional bank, directorate and linked risk category. Recognition lag, unrecovered aging, recovery prospects, mapping gaps and source tables support investigation. Near misses have no financial recognition date and are not counted as missing recognition records.

New board packs capture an immutable operational-loss annex. Old packs stay unchanged. Published packs preserve figures, source context and charts when live records later change. Copilot explanations use the actual visible loss filters or the captured report snapshot.

## Build, verification and boundary

Run `python3 build.py`. The Node suites in `docs/TEST_REPORT.md` exercise actual-source models, commands, routes and actions. They substitute the browser shell and do not validate real layout, file persistence, downloads or printing. Browser execution remained blocked by the available environment; no V2.9 screenshot or browser-layout claim is made.

Run `python3 verify_reference.py` to verify the untouched release. Rebuilding or rerunning tests can change manifest hashes.

This updates the **interactive design package**, not a production deployment. Domain commands demonstrate scope, roles, review separation and stale-record checks in local state. Read views retain selected organizational scope; browser state is not an authenticated data-access boundary. Production needs server authorization, transaction/concurrency controls, durable storage, scheduling and notification delivery. The demo sends no real notifications.
