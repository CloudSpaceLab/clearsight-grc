# ClearSight V2.7 — Authority and shared records

The reference demonstrates one connected UI. It must not be transplanted as a new bank backend.

## Ownership

Framework versions own canonical requirements; program requirements reference them with scope/tailoring. Form versions and bindings own the collection instrument and exact target. Observations, document versions and response snapshots supply evidence. Program requirement evaluations remain the conclusion owner. Risks, loss ledgers, RCSA, indicators, KRI returns and privacy records retain their established owners.

Documents have one identity and immutable-by-demo-workflow versions. Record links pin versions. File bytes are distinct from metadata. Approval requests capture source versions and digests. Independent decisions produce common receipts but preserve each domain's gates. Work is a projection, not another approval engine.

Reports reuse the same scope, snapshot, periods and monetary calculations as source lists. Published packs retain their captured data. Copilot uses these read models; reviewed proposals invoke the normal action command.

## Presentation contracts

- Global scope is Branch → Department → Unit in the logo header. All means permitted descendants in production; it is not permission bypass.
- Record ownership never changes from a navigation filter. Invalid saved scope and explicit invalid IDs block rather than widen/substitute.
- Current posture, occurrence-period losses and monthly returns retain distinct time semantics.
- NGN values are integer kobo; net loss is derived. KRI ratios aggregate numerator/denominator, not percentages. Missing observations are not zero.
- Publication, approval, evidence acceptance and compliance are distinct statuses.
- Full pages handle durable records and decisions, wizards handle staged setup, direct form editing handles composition, short dialogs handle atomic choices.

## Production work

Preserve authenticated tenant/actor boundaries, revision checks, append-only source history, private execution and provenance from the real repository. Add concurrency, storage, malware handling, lifecycle/retention, signing-provider integration and service-level testing before operational use. No existing production API, migration or authorization contract is superseded by this design package.
