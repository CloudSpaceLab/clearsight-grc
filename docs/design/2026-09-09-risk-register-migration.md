# Vendor risk register migration

The approved direction is to migrate historical findings into vendor-deficiency issues with individual actions. The user requested intelligent matching and delegated interaction decisions to implementation.

Imports detects a findings register, retains complete rows, and proposes assessment groups from explicit serial numbers and contiguous continuation rows. Repeated values from vertically merged cells stay within the same numbered assessment. Suggested continuation context is identified. Blank responsibility is suggested from its assessment, never across a new assessment. A single review confirms the proposed grouping and mappings. The original workbook remains unchanged; row provenance retains the extractor's cells, including expanded merged-cell context.

One mapping resolves each repeated responsibility name to an eligible internal person. Each vendor/service group resolves to an existing legal-entity-scoped relationship. Vendor responsibility retains a bank accountable owner and vendor association. Historical assessor, business team, dates, ratings, status and comments remain source facts. Import creates initial-review issues and planned actions; it cannot certify a vendor, verify a finding, impersonate a historical assessor or send external invitations. Existing vendor work commands handle subsequent reviewed requests.

The recommended first slice is a deterministic, bounded migration with human-reviewed matches. A one-off script would omit repeat-use recovery. An AI-only importer would make routine migration depend on provider availability. Deterministic header recognition, continuation suggestions, name normalization, existing directory/vendor searches and duplicate receipts cover the supplied workbook without either limitation.

The workflow is: upload → review proposed groups and unresolved mappings → import findings → receipt with issue links. Selections are saved with a versioned migration draft; retry reuses the source receipt. A repeated identical file in the same legal entity reuses its imported findings. Changed files require a new review and never silently overwrite current issues.

Implementation uses existing extraction, authority resolution, canonical Matter/Action events, vendor relationship links and transactional outbox. Material commit revalidates source version, legal entity, vendor versions and eligible assignments. Findings, actions, links and the receipt commit atomically. Maximum 100 findings per reviewed migration; larger or incomplete sources require a smaller complete file. Search is bounded before presentation. No workbook contents enter committed fixtures.

Required fixtures: the five-finding/two-service shape, blank continuation context, duplicate person names, vendor responsibility, no eligible candidates, invalid date, incomplete extraction, source/version conflict, unavailable API, successful import and duplicate retry. Mapping precedes findings; desktop pairs related fields and mobile stacks them. Native labelled controls and existing theme tokens apply. Tests cover provenance, scope, authority, idempotency and transaction rollback; render light/dark at 1440 and 390 pixels and check copy quality and accessibility.
