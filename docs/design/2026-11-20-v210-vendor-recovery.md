# Vendor assessment recovery and clarification

Status: partial v2.10 implementation; not accepted for production cutover. Reference: `clearsight-v2.10/vendor-onboarding.html`, SHA-256 `380a5b9b7c64eb9b83460ee6d68f0796c78b796d8eb8ff7aab8c086514de2107`. The reference uses prototype-local data and is not an authority or delivery source.

The current assessment workspace now exposes three existing server operations. A failed setup job can be retried only for the matching pending assessment and the current owner route. A collecting assessment can replace the existing recipient's invitation under the separate reissue route; the form warns that the old link may stop working and that the response deadline caps access. An independently authorized reviewer can request clarification for visible submitted questions while the assessment is under review. The reviewer supplies the recipient, selected questions, message, deadline and invitation period; the requested deadline is bounded by the review due date. None of these actions supplies a client-selected actor, reviewer, tenant or legal-entity identity in its command.

The server re-evaluates the route and expected assessment version on execution. Replacement and clarification can have prepared intermediate records, so even a reported error is treated as an unconfirmed outcome and further submissions are withheld until the assessment is reloaded. Success is shown only for a matching assessment and recognized delivery state; invitation URLs and tokens are never rendered. A queued setup result is matched to the same assessment and a later version before the queue message appears.

Required states are loading, authorized and denied route, failed versus queued setup, collecting with and without a current request, historical assessment, selected and unselected clarification fields, invalid deadline, email delivery failure, access not issued, mismatched receipt, and an uncertain command outcome. Tests mock the existing API rather than sending real email. Complete onboarding dossiers, independently assigned participants, remediation, handling a prepared request with no issued invitation, and a live backend journey remain incomplete.

On 20 November, the setup-failure and replacement-invitation states were rendered with intercepted sample responses at 1440, 768 and 390px as `.playwright-mcp/v210-vendor-{setup,reissue}-{width}.png`; no horizontal overflow was detected at those widths. The sample does not exercise command delivery or live authority. Same-screen v2.10 source comparisons, 1280/1024 recovery renders, keyboard and denied/error state review, and live backend verification remain outstanding. This is not a visual acceptance or authorization claim.

Document-link confirmation compares the receipt's source response revision as well as its submission, field and artifact when a revision was selected. A missing or different revision is an unknown outcome requiring assessment reload, not a confirmed link. This check does not replace the server's scoped source verification or independent review.
