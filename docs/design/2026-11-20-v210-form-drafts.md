# Forms drafts and approval

Status: partial v2.10 implementation, not production acceptance. Reference: `clearsight-v2.10/forms.html`, SHA-256 `8d8a5969b3ceb5bb9cfc09d5ec023b35e0164ae488ebb93143285959925b237c`, and its form creation/builder interactions. Prototype records are not production data.

The new Forms library provides a fresh draft creation path for ordinary text, yes/no, date, number, percentage, document, single-choice and multiple-choice questions. Choice questions require 2–50 distinct options. It checks the signed-in actor's current legal-entity creation route, then calls the existing versioned form-template command. Form details show only transitions advertised for the actor by the backend; non-pending transitions also check the service's materiality-three owner route. A revision editor can update the form name, purpose and existing question labels, change types for simple questions without dependent rules, and add questions to a selected section while retaining the stored field, section, scoring and ownership settings. It requires the server's current revise permission and creates a new draft version; it does not modify the published revision. Transition commands retain maker-checker enforcement in the backend.

Unconfirmed create or revision outcomes withhold a second command and keep entered text visible for comparison. Definite validation failures keep the form editable. Question labels enforce the backend's 200-byte UTF-8 bound. Required states include loading, no authority, authority-service failure, partial form definitions, failed validation, stale or unknown command outcome, successful draft and approval transition. Editing complex types or removing already-persisted questions, rich scoring, conditional rules, live source configuration and named assignments remain incomplete. Form authoring is therefore partial.
