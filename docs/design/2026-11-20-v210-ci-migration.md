# V2.10 CI migration status

The new application and evidence entry dependency graph is checked by `npm run check:runtime-truth`. It rejects imports from the retired component and stylesheet trees and prevents fixture code from entering the customer runtime. The UI evidence workflow also captures the sample form-choice and vendor-document empty states at five widths. These checks are additive and do not establish full-screen or production acceptance.

The remaining checks intentionally still block integration:

- `npm test` includes legacy component tests whose implementation modules have been removed. Each must be migrated to the corresponding new workflow, or retired with an explicit mapping to equivalent new coverage; deleted imports are not passing tests.
- `npm run check:ui-contracts` currently fails three checks for retired CSS and component-token paths: the full token/cascade contract, document-import styling and migration manifest. The shell-only token and focus checks are not equivalent to those broader requirements. Replace each remaining check only after its current-runtime requirements and evidence exist. The focused-sheet check now targets the current native modal component used for the mobile Forms outline, including retained browser top-layer and sticky-content checks; other future overlays still need their own acceptance. The reference-integrity check now pins the v2.15 manifest and all 398 reference files; that package must be available unchanged in CI. The older v2.9 verifier fixtures remain as unit tests, but the absent historical v2.9 package is not verified by this check.
- CI schedules the v2.15 mobile navigation browser check, including a real hit test for the 44px close control over a competing positioned layer and focus, inert, route and session-expiry checks. This is coverage for the current drawer only and does not verify other overlays. A local run at 390, 768 and 1440 pixels is retained under `docs/evidence/2026-11-21-v215-shell-stacking/`.
- `npm run review:ui` and later UI workflow steps expect the original workflow and evidence manifests. The new reference requires complete source/runtime comparisons and interaction, permissions, empty, denied, light/dark, accessibility and responsive evidence before those expectations can be reconciled. The two v2.10 captures are not a substitute for that review.

These failures must not be masked by excluding old tests or dropping browser scenarios while the associated capabilities remain unavailable. A passing subset or screenshot count does not authorize production cutover.

The retired `FormBuilder.responsive.test.tsx` now exercises current form creation and its question outline, including focus on the selected question and preservation of entered form details. The new authoring workflow keeps those details inline and generates the form code; it does not reproduce the retired Settings sheet. Responsive browser evidence for the shared outline in form editing is retained in `docs/evidence/2026-11-21-v215-focused-sheet/`. This mapping does not establish parity for the remaining legacy builder tests.

The retired `FormBuilder.send-recovery.test.tsx` now exercises the current separate save and send steps through the application route. It verifies the saved draft's exact version and name remain visible after an unconfirmed approval transition, and that the unconfirmed transition is not offered again without a reload. The old combined save-and-send dialog no longer exists.

The retired `VendorActivationPanel.test.tsx` now tests activation refresh through the current VendorReview after assessment progress. Its component-level scope, stale read and command, policy and gate, authority, receipt, recovery, duplicate-command and active-refresh coverage is maintained in `web/src/v210/VendorActivation.test.tsx`. Activation uses the backend's nonempty, maximum-2000-character rationale contract; the retired UI's additional 20-character minimum is not carried forward. The responsive activation fixture and its limitations are retained in `docs/evidence/2026-11-21-v215-vendor-activation-refresh/`.
