# Integrations and data sources layout

The pinned Integrations HTML leads with a page heading and Sources, Field
mapping and Sync history views, then a source register and selected-source
context. The existing configuration area only exposes document imports;
connected-source configuration, mapping and sync-history readers are not
available. Adapt the page anatomy with the shared shell, tabs and surfaces.
Show those limitations explicitly and retain the existing document-import
handoff and its deployment flag. Do not create source records, health counts,
filters, connection actions, mappings or history without their contracts.

Preserve the Settings route and use route-backed local tabs so Back, Forward and
direct links select the same view. At desktop widths, place available import
context beside the source state; stack at tablet and phone widths. Compare
1440, 1280, 1024, 768 and 390px source/runtime, both runtime themes, keyboard
navigation, permission/disabled states and import handoff. This is partial V2
integration; selected source, real connection actions, source health, filters,
mapping and sync history remain open, as do operational acceptance gates.
