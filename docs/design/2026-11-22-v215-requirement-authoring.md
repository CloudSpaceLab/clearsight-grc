# Program requirement authoring

The Program layout reference is `clearsight-v2.15/programs.html` (SHA-256 `2C524C7D4301165DC0273E321B34219F1AAE73D3846A29A5C9852063B8B5D2B6`). This change extends the current Program detail workflow; the reference does not establish authority or create a requirement.

The Add requirement action requires the current Program version and a positive `program.requirement.add` authority result. The owner enters the source and section, obligation strength, party, action, object, text and effective date. The integrated backend records a draft requiring independent review; no source ID or bank-specific party is invented. The UI checks the returned draft's identity, text, source, semantics and effective date before reporting success. A changed Program or an unconfirmed response cannot be retried as a new command. An in-flight response for a previously selected Program is ignored. Existing applicability decisions retain a rationale only when the selected decision requires one. Drafts are identified as requiring review and cannot be treated as approved. The review proposal and decision UI is not implemented in this tranche.

Synthetic draft, add and not-applicable states at 1440, 768 and 390 pixels are in `docs/evidence/2026-11-22-v215-requirement-authoring/`. The browser check verifies required fields, blocked incomplete save, draft labeling, conditional rationale and horizontal overflow. Renders were inspected; the desktop form width was constrained after inspection. Fixtures do not prove authorization, backend writes, source validity, dark-theme behavior or full screen acceptance. The integrated candidate's routed `TestRequirementReviewHTTPIndependentAuthorityAndScope` verifies explicit draft creation with source semantics and stale-version rejection, as well as independent review and entity-scope checks.

The legacy `ProgramRequirementAuthoring.test.tsx` remains unresolved: its first test requires creating a new Program and then authoring its first requirement. The v2.15 Program register does not currently provide Program creation, so replacing that test with an existing-Program test would discard a workflow. Existing Program authoring and applicability requirements are covered in `web/src/v210/ProgramRequirements.test.tsx`.
