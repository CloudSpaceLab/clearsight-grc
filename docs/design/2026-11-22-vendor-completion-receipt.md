# Vendor review completion receipt

The assessment completion form now accepts a response only when the assessment ID, tenant, legal entity, relationship, next version, completed status, conclusion, rationale and uncertainty match the expected result, and a reviewer and valid completion date are present. A mismatched response keeps the completion outcome unknown and asks the user to reload. Only one submission can be in flight; changing vendor scope discards a late response. A 401, 403 or 404 clears the assessment and requires a fresh scoped read. The server remains responsible for verifying the reviewer and current authority. If a confirmed completion is followed by a refresh failure, the form reports the saved result separately.

Synthetic completion, access-denied and unconfirmed-receipt states are recorded in `docs/evidence/2026-11-22-vendor-completion-receipt/` at 1440, 768 and 390 pixels; the evidence script asserts that the form is no longer available after an unconfirmed result and that the viewport has no horizontal overflow. An initial mobile inspection found the alert visually resembled ordinary supporting text; it now uses the shared danger text token. The existing `docs/evidence/2026-11-22-vendor-collection-scope/` images provide the prior vendor detail baseline. These fixtures are not evidence of production authority or whole-screen acceptance. Existing legacy due-diligence tests remain until all their material workflows have equivalent coverage.
