# Spreadsheet rows in vendor form proposals

The supplied checklist is organized as one requirement per row, while the supplied risk register records historical findings and recommendations. Proposing their column headings as questions loses the work users need to perform. This bounded change gives both formats a useful starting draft through the existing document-import and governed Forms workflow.

XLSX extraction now retains complete row cell values in the existing structured extraction elements. The original row text and positional worksheet/row anchor remain available. A proposal recognizes a requirement/checklist heading with applicability, evidence or timing context, or findings with recommendations and status. Recognized sheets produce one optional, unscored long-text field per populated requirement/finding row. Generic data tables retain the existing column-oriented behavior. Form labels, descriptions and sections remain editable in the existing builder.

Checklist context retains the source reference, applicability, timing and evidence expectation for author review. Historical follow-up fields retain recorded status/deadline and recommendations before long finding text. Per-field warnings require authors to confirm scope and distinguish internal work from vendor questions. No vendor is matched, finding created, applicability determined, evidence accepted or compliance conclusion made. Proposal acceptance still creates a draft; ordinary independent approval remains necessary before reuse.

The implementation uses the existing proposal, field, description, source-anchor and unresolved-item interfaces. There is no new API object, database migration, external access route or UI control. Row values use existing persisted extraction details. The parser and proposal provenance versions advance so the changed interpretation remains identifiable.

The planned and verified sequence was: add failing XLSX-to-proposal tests; retain bounded structured rows; recognize the two explicit layouts and generate draft fields; preserve generic tables; check the actual supplied files read-only; run the complete document-import test package. A second failing test exposed long finding text displacing historical dates; context priority was corrected before verification.

Scope limits: this is draft authoring, not a governed requirement-set engine or a historical-register migration. Header synonyms are intentionally limited; other layouts use the manual builder. Merged blank vendor/service cells are not guessed or copied into a match. Existing positional worksheet identifiers are retained. Files extracted by the older parser need uploading again to retain structured rows. Form limits remain 200 fields, 20 sections, 200-byte labels and 1,000-byte descriptions; omitted fields and shortened row context are reported separately. Full source rows remain available for review. Source legal references and deadlines require the organization's own confirmation before any policy is activated.

For the visible proposal review, retain the existing per-field warnings and source excerpts. Creating a draft does not need another acknowledgment checkbox. Before distributing a form, the author must edit field types, requiredness, applicability controls, wording, reviewer rules and evidence questions for the intended recipient. Internal findings, comments and responsibility details must be removed from recipient-facing questions where disclosure is not appropriate. The broader mapping, request grouping, evidence reuse and continuing-use decision remain separate workflow capabilities.
