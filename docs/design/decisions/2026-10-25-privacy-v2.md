# Privacy Overview and ROPA layout adaptation

Date: 25 October 2026
Scope: #462; Privacy Overview, processing activity register and selected activity inspector.

## Problem and authority

The released Privacy destination combined a six-metric summary, coverage details and register in one page. It lacked the approved local menu, placed every first record below the first viewport, and replaced the collection with a standalone record page. The preserved main baseline at `02dd0b4f066ba58ec17cf0e2588437efe5e856fd` places the first activity identity at approximately y=944px on desktop, 1198px at 768px and 2009px at 390px.

The immutable source is [`privacy-workspace-preview.html`](../references/clearsight-2026-10/source/clearsight-privacy-data-designs/privacy-workspace-preview.html), SHA-256 `4baf53940862d9a3af1fbc1be32da7b27595a22efb0646759cb91685a0cb5e8d`. The accompanying source HTML, CSS, JavaScript and design notes are unchanged. The [21 October navigation decision](2026-10-21-v2-navigation-adaptation.md) still governs the shared primary menu and rail.

## Composition and supported navigation

- **Privacy & data** is the persistent page heading, with actual organization/entity context and the existing Reports and Refresh actions. There is no runtime create or period control without a supported workflow.
- The existing `#ropa` route remains the ROPA register. `#ropa/overview` exposes the already implemented summary through the same route/parser owner. The local shared `Tabs` menu uses source order **Overview / ROPA**, with the current route determining selection.
- ROPA follows the approved section heading, compact search/status controls, current-page count and record table. The summary is no longer above the register. DataTable's existing container-responsive cards replace the table when its usable width is at most 700px.
- The columns follow source anatomy: activity identity, data subjects, lawful basis, review, owner and recorded lifecycle status. The API has no department field, so there is no invented department. Purpose remains in activity details. Existing stored lifecycle filters replace the prototype's synthetic review filter; they are not relabelled as review-currentness filters.
- `#ropa/activity/:id` keeps the same mounted register beneath a shared `FocusedSheet`. The inspector is 480px wide and becomes full-width under the existing shared phone breakpoint. It uses the current exact activity and history readers; it does not construct a full record from a list row. The record heading and facts precede closure information, related categories, recipients, systems and histories.
- Overview adapts the source's four-measure row and primary/context layout to existing data: processing activities, in progress, reviews overdue and missing lawful basis; then lifecycle counts, missing owner/data-subject counts and a coverage/freshness rail. Source department bars, DPIA pipeline, incident series, due-review priorities and Copilot are not backed by these APIs and are not presented as actual data.
- DPIAs, Breaches, Vendor reviews and Requests remain unimplemented source destinations. Their tabs and sample actions are omitted rather than routed to unrelated collections. This explicit menu reduction is not whole-source functional acceptance.

## Data, behavior and authority

The existing ROPA APIs, bounded queries, opaque cursors, exact readers and Reports owner remain unchanged. The summary includes ended activities, so counted Overview drills use the existing `include_retired=true` query and show a removable **Includes ended activities** scope chip. Removing that chip or clearing filters restores the ordinary current register. Counts are never subtracted or reallocated in the client. Empty or failed later pages retain a previous-page action. Search/status changes clear the cursor; pending responses are aborted and ignored. Each tab loads its own read only when selected. Moving into and out of a record preserves the current register query and cursor, without issuing another collection request. Browser Back/Forward and cold entry retain their ordinary URL meaning.

App keys the workspace by tenant, legal entity and principal, so retained queries and record selection cannot cross verified identity changes. This is UI isolation; server authorization remains the boundary. A denied list is distinct from an empty successful result. Missing cursors retain the existing incomplete-page warning, and metric coverage/staleness are preserved rather than converted into healthy results. There are no client-derived enterprise totals or percentages.

The API does not supply a bank timezone or authoritative per-record overdue flag. Register and inspector show recorded review dates; pending reviews remain pending. Only the server summary supplies an overdue count, with its retained as-of/freshness context. Browser UTC dates do not establish missed deadlines. Read-only empty sections no longer direct users to unavailable category/recipient/system/review commands.

The prior record reader treated an empty blocker list as **Ready to close** and displayed a disabled closure command without a runtime action. It now reports **No closure blockers recorded** for an unclosed record and offers no unsupported command. Closure eligibility and material authorization are not inferred from the read response.

## Responsive and interaction contract

| Surface | Desktop/tablet | Phone |
| --- | --- | --- |
| Page heading | Identity and existing actions beside one another | Stacked identity and 44px actions |
| Local menu | Source-order underline tabs, route selection | Same visible tabs with shared keyboard/focus handling |
| Register controls | Search, stored status and current-page count beside one another | Stacked controls with readable count/reset |
| Records | Source-shaped table; cards when the content container is 700px or narrower | Labelled record cards and full-width detail action |
| Overview | Four primary measures; two primary sections and 304/285px context rail | Two metric columns; one primary column and stacked coverage |
| Inspector | Shared 480px sheet, current record heading and label/value facts | Full-height/full-width sheet; no background document scrolling |

No new palette, token, density or interactive primitive is introduced. Feature CSS arranges the existing Button, Tabs, SearchField, SelectField, DataTable, MetricCard, RankedBarList, Surface, StatusBadge, Notice and FocusedSheet contracts.

## Verification and boundary

Focused runtime verification covers route round-trips; source-shaped menu selection; unknown, zero and stale coverage; supported server query/paging; late-response cancellation; preserved search/page through record opening and return; exact record reads outside the current page; denied versus empty results; closure wording; working-language copy; and the existing API contract. Baseline captures retain all five approved widths in both themes. Full source/runtime, keyboard/touch, history and accessibility results are recorded with the final evidence receipt rather than inferred from unit tests.

This is **partial V2 layout integration**. Formal whole-screen acceptance remains **0/19**. The reduced domain menu and Overview substitutions are explicit adaptations. Four-actor execution, live backend authorization, source-to-report reconciliation and production cutover acceptance require separate evidence.
