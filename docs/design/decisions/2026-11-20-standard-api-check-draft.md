# Standard API check draft — partial

The existing connected-data builder now defaults to the requested `result` / optional `message` contract and uses the chosen boolean or numeric type during real endpoint inspection. An explicitly selected other-record-fields mode preserves the existing stable-key workflow. Sample validation is local and does not create a source or contact an endpoint. A standard source uses a keyless draft binding; messages are not retained. Numeric thresholds must be finite JSON numbers, and boolean expectations use yes/no choices. The configured maximum age is carried into the monitoring-check request when an active binding is available.

The source catalog currently creates only draft connections, views and bindings, while the monitoring service requires an active current binding even for draft check creation. The builder therefore does not ask for an unsavable condition, stops after recording the source draft, and explicitly says source approval is unavailable. This is not a live form question, assessment result, approved source or production cutover. Endpoint inspection can leave draft catalog records if a later step fails; cleanup and transactional source configuration remain outstanding.

Source creation no longer performs a separate post-commit catalog registration. PostgreSQL already checks the authoritative source row; the in-memory catalog now performs an exact tenant/source lookup against the evidence repository. A committed source is acknowledged without a later registration failure. This does not make the subsequent connection, view, inspection and binding steps atomic; drafts can still remain after those later steps fail.

The current implementation is in Program connected-data setup, not yet the reference's question-specific adoption dialog. `api-check-after` in the 2026-11-20 Codex visualization directory contains fixture renders at five widths in both themes. The evidence transport simulates inspection and does not contact the sample endpoint; adapter tests separately exercise a local TLS endpoint. These checks do not establish production authority or network integration acceptance.
