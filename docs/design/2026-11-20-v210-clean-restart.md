## 20 November response and vendor review tranche

All previous CSS under `web/src/components`, `web/src/design-system` and the root of `web/src` has since been removed individually. Some previous React components remain on disk. A dependency-graph check verifies that the production and evidence entries do not import the old component or design-system trees; only styles in `web/src/v210` remain. Legacy UI tests still reference removed files and the complete legacy suite has not passed.

The new response workspace uses scoped response discovery, exact revision answers, linked document pages, named submitters when provided by the server, server-authorized whole-response decisions and versioned review history. The vendor workspace opens exact relationship/assessment records, starts onboarding assessments, requests information, records review outcomes and document decisions, and checks activation requirements and authority before activation. These are partial workflows; reissue, clarification and complete onboarding dossiers remain outstanding. Activation and review have not been verified against a live backend.

Invited capture uses the existing link or email-code access APIs, keeps credentials in memory, supports ordinary questions and file/photo uploads, and uses the shared workspace version and field sequences. Unsupported bound, signature and vendor-document fields block submission. Conflicts are presented for review and an uncertain submission is not retried automatically. Internal named-assignment creation is deliberately not exposed: the current authenticated internal submission path does not produce the revision and review history created by the capability-session workspace. A new recipient-bound authenticated backend path is needed before enabling it.
