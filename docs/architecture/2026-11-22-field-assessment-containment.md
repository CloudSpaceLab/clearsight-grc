# Field assessment decision containment

Field-level assessment history remains available under the existing scoped read authorization. New assessment decisions are unavailable, and assessment reads report `may_review: false`. The registered POST returns 503 after verified identity and scope checks. The service rejects direct callers before reading assessment material or writing events. The private test seam exercises the unexposed implementation only; production composition does not enable it.

The PostgreSQL prerequisite checks current route, effective reviewer roles for all changed fields, session, subject visibility and respondent separation in the same statement as the versioned assessment insert. The selected route source and statement time are included in the immutable decision and assessment snapshot; field records, event and outbox are written in that transaction. Focused PostgreSQL tests cover revoked authority, expiry during a response lock, replacement by a same-rule/version route lacking the field role, receipt and timestamp parity, conflict, correction and injected outbox rollback. This is not complete authorization proof: route/role and delegation parity require independent review across supported origins and scope conditions.

The gated PostgreSQL command requires a UUID idempotency key. A tenant/entity/reviewer-scoped unique receipt and transaction lock serialize attempts. The receipt records the normalized decisions and expected version with the assessment. Replay rechecks verified session, subject visibility, independence and every current field reviewer role in the authorized statement, compares the exact input, and returns the original assessment version. Tests exercise simultaneous same-key calls, altered payload, cross-actor and cross-response denial, revoked authority, changed role, expiry, later corrections, rolled-back writes and the populated migration rollback guard. The in-memory adapter applies the same keyed replay contract. Migration 000155 refuses rollback while receipts exist.

Before enabling decisions, establish full independent authority and delegation parity, and add client attempt retention that does not persist sensitive rationale. Bind each attempt to the verified tenant, entity, actor, response and expected version. Keep only the request key and non-sensitive attempt metadata in session storage; after reload, ask for the original field decisions and reasons again. A retry that could create a decision must be explicit, and a changed attempt requires a new key only after a definite no-commit result. Independently review the route, receipt, replay, client recovery and supported-origin scope before exposing controls.



Identity limitation: the signed request envelope and its timestamp are verified at HTTP ingress. The assessment transaction rechecks the actor's issued and expiry times, but the identity contract has no transaction-visible staff-session revocation state; SessionID alone is not a revocation check. Before enablement, define whether the signed identity remains authoritative until expiry or add a supported current-session check, and prove behavior when a session is revoked or the ingress signature window elapses while a command waits.
