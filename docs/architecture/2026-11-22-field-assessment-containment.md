# Field assessment decision containment

Field-level assessment history remains available under the existing scoped read authorization. New assessment decisions are unavailable, and assessment reads report `may_review: false`. The registered POST returns 503 after verified identity and scope checks. The service rejects direct callers before reading assessment material or writing events. The private test seam exercises the unexposed implementation only; production composition does not enable it.

The PostgreSQL prerequisite checks current route, effective reviewer roles for all changed fields, session, subject visibility and respondent separation in the same statement as the versioned assessment insert. The selected route source and statement time are included in the immutable decision and assessment snapshot; field records, event and outbox are written in that transaction. Focused PostgreSQL tests cover revoked authority, expiry during a response lock, replacement by a same-rule/version route lacking the field role, receipt and timestamp parity, conflict, correction and injected outbox rollback. This is not complete authorization proof: route/role and delegation parity require independent review across supported origins and scope conditions.

Before enabling decisions, require a stable request key scoped to verified tenant, entity and reviewer and complete the exact-input receipt workflow. A unique database constraint and transaction-bound serialization must prevent concurrent duplicate writes. On replay, recheck verified session, current subject visibility, independence and the current field-review route in the same statement as the receipt lookup; reject mismatched response or input without returning another receipt. Return the originally committed assessment version, not the latest version. Test lost responses, no-commit retry, concurrent same-key attempts, changed input, cross-response or account reuse, revoked authority, expiry and rollback in PostgreSQL. Add client retention that does not persist sensitive rationale and makes any retry that could create a decision explicit. Independently review the route, receipt and recovery before exposing controls.

The new receipt fields are optional in historical JSON; old rows are not backfilled.

The gated PostgreSQL implementation now supports an optional scoped request key, serialized within the transaction, with exact-input replay under current visibility and reviewer authority. Migration `000155` retains historical rows without receipt keys and refuses rollback after a keyed receipt exists. Tests cover concurrency, replay, revocation, expiry, changed input and transaction rollback. The key is not yet required, the client does not retain it, and end-to-end uncertain-outcome recovery and broader independent route parity are still required; production decisions remain disabled.
