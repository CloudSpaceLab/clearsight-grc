# Web session refresh containment

The PostgreSQL session store refreshes the token presented by a request only while its existing unexpired row remains present. Logout and rotation delete the old row; an in-flight refresh cannot recreate it. New and rotated tokens use insert-only writes. An unsuccessful delete of a previously loaded token prevents a competing rotation. The request-scoped token hash classifies storage operations and is not an identity claim.

Real-PostgreSQL tests exercise logout and idle refresh, rotation races, expiry and cleanup, duplicate cookies, token collisions and store failures. A stale response may still overwrite a newer browser cookie with an unusable older cookie, requiring sign-in again. A genuine session-store failure after a material handler commits may still affect the response; that post-commit behavior remains unresolved. The existing signed identity contract does not provide transaction-visible staff-session revocation. These limitations block production acceptance and do not enable field-assessment decisions.
