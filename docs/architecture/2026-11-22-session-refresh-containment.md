# Web session refresh containment

The PostgreSQL session store refreshes the token presented by a request only while its existing unexpired row remains present. Logout and rotation delete the old row; an in-flight refresh cannot recreate it. New and rotated tokens use insert-only writes. An unsuccessful delete of a previously loaded token prevents a competing rotation. The request-scoped token hash classifies storage operations and is not an identity claim.

Real-PostgreSQL tests exercise logout and idle refresh, rotation races, expiry and cleanup, duplicate cookies, token collisions and store failures. A stale response may still overwrite a newer browser cookie with an unusable older cookie, requiring sign-in again. For an unchanged loaded session, a failed same-token idle refresh is logged without affecting the response; the prior idle expiry remains in force. Failures while creating, changing, rotating or deleting a session still propagate, including after a material handler. The existing signed identity contract does not provide transaction-visible staff-session revocation. These limitations block production acceptance and do not enable field-assessment decisions.
