# Vendor form assessment acceptance

Scope: extend existing Forms and Vendors; local implementation on `codex/vendor-field-assessment`. Deployment and actual vendor email delivery are separate acceptance steps.

| Journey | Required proof |
| --- | --- |
| Uploaded workbook to form | Ordinary document extractor preserves the supplied risk register as source material; imported draft still requires bank configuration and approval. Source Medium ratings are not silently converted into approved numeric scores. |
| Bank field configuration | Field mode, weight, required review, named reviewer role and rubric survive form serialization; invalid configuration blocks the draft. Existing automatic rules remain usable. |
| Review a response | Immutable answer, exact template/response version, missing evidence, automatic contributions, bank judgement and rationale are visible. A changed version, revoked reviewer or self-review is rejected. |
| Vendor overview | Pending counts precede pagination and do not disclose draft values. Missing/provisional scores never count as low risk. Current final high risk can be filtered and opened. |
| Request multiple vendors | One selected recipient per relationship, verified current owner route, immutable form version and deadline; duplicate target rejected; same batch retries one canonical request; changed payload conflicts. |
| Automate a result | Contextual guardrail draft or named existing policy, simulation, separate checker, effective dates, expiry, kill switch, bounded execution, rollback and execution history. Automatic and bank-assessed bases stay distinct. |
| Recovery and scope | PostgreSQL transaction rollback leaves no assessment/event fragments; tenant/entity/request scope and keyset paging hold; policy corrections cannot execute against stale bank decisions. |
| Presentation | Desktop/narrow, light/dark, keyboard, empty/error, authoring/review and partial request states render without blocked actions or horizontal overflow. |

Reference workbook: `Sample Third-Party Risk Register (1).xlsx`, sheet `2026 Register`. Five risk rows describe two services, with merged service/overall-rating cells; all source ratings are Medium and statuses Open. The repeated masked provider value `xxxxx` is not an identity key. The current authoring flow must preserve source anchors and ask the bank to approve assessment rules rather than inferring scores from these labels.

All cases recorded zero application errors, zero horizontal overflow and zero axe WCAG A/AA violations. States cover the vendor overview, forms, empty/error results, field authoring, policy setup, bank review, partly replaced responses, paged history, read-only historical review, saved judgement and poor-result filtering. These are explicitly labelled sample fixtures, not live bank data.

Keyboard ArrowDown and Escape opened and dismissed the filter without changing the selection. History loaded the next keyset page for the same vendor relationship, opened the selected historical response revision and exposed no judgement input or save command. [Focused interaction screenshots](../screenshots/vendor-form-assessment/vendor-assessment-evidence-interactive/manifest.json) repeat the 12 saved/filter cases with viewport captures for legibility.
