# Shared blue theme and Program measure density

The approved [Program HTML](../../design/references/clearsight-2026-10/source/clearsight-program-designs/program-workspace-preview.html) uses blue for navigation and actions. The previous runtime used cyan in those roles; the [Program baseline](../2026-11-02-program-title/before-desktop.png) records that state. Shared action, focus, information and legacy accent styles now resolve through blue theme tokens. The light primary action is slightly darker than the source example to retain white-text contrast. The brand mark retains separate teal and violet colours, and warning, success and error meanings remain separate.

The Program overview retains each measure's quality, source/version context and action while reducing card padding and gaps. The five viewport captures per theme show the compacted Program measures. On the example Program, desktop cards changed from approximately 196px to 172px; phone cards remain 149px. The approved source's SHA-256 is `b91aa4a96bfae4fc712f49e883996eb770d74dc3ae4b588ab6e573b4ec9d846f`. At 768–900px, the title and actions now share a row, as in the [768px source capture](program-source-768.png); below 768px they remain stacked. On the fixture, the first measure moved from y=486px in the [reconstructed pre-change baseline](program-tablet-baseline-768.png) to y=422px in the [updated render](program-tablet-after-768.png). Renders at 767, 768, 820, 900 and 901px and an injected long-title layout probe in both themes show no overlap or document-level horizontal overflow. The long title is a layout probe, not a stored Program. The source-backed control-area distribution remains an open structural and data gap.

Final captures cover Program, Forms, Vendors, Work and Home at 1440×900 and 390×844 in both themes, using the evidence fixtures. Captures also cover Framework Library, Risks, RCSA, Losses, Privacy, Reports, Configuration and Notifications at both widths and in both themes. Some of those fixtures show unavailable data, so they do not exercise every populated state. The first palette review found low-contrast selected navigation text in light mode; it was changed to the darker interactive-text token before the final captures. On these 13 desktop routes and the additional eight phone routes, axe's colour-contrast rule reported no definite violations in either theme, with one incomplete rule result per run requiring manual review. This is not a full accessibility or all-workspace colour audit. Separate 1440, 1280, 1024, 768 and 390 Program captures show no document-level horizontal overflow; visual review does not replace long-content, keyboard, authorization or live-data checks.

Phone review found a vertical scrollbar in Reports and Privacy tabs: the selected indicator extended one pixel below the scrollable tab list. The shared indicator now remains inside its tab. Before the change the Reports and Privacy tab lists had scroll heights of 45/48px against client heights of 44/47px; afterwards those heights match. The `tabs-*` captures show the corrected Reports, Privacy, Risks and People lists in both themes. Horizontal scrolling is retained: at 390px, keyboard End and Home selected and revealed the last and first Reports tabs respectively. The earlier `reports-*-phone` and `privacy-*-phone` files preserve the pre-correction state.

The populated People fixture revealed 13 light-mode contrast failures in avatar initials: the first blue action token had only 4.15:1 contrast against the secondary surface. The light primary token was darkened, and a token regression now checks both primary-button text and primary-coloured text on that surface. The `people-final-*` captures and an axe recheck at 1440px and 390px in both themes found no definite colour-contrast violations; each run retained one incomplete rule result. The earlier `people-light-390.png` records the pre-correction state.

After the final token adjustment, `final-program-*`, `final-reports-*`, `final-privacy-*` and `final-risks-*` capture the corrected tablet/phone states in both themes. Their colour-contrast checks found no definite violations and one incomplete rule result each. These final captures supersede earlier comparison images where the shared blue was lighter.

The `populated-*` captures cover Framework Library, Risks, RCSA, indicators, losses, Vendor register, Reports and Notifications using their named evidence fixtures at 1440px and 390px in both themes. The 32 axe colour-contrast runs found no definite violations; each retained the `color-contrast` incomplete result. For the People fixture, incomplete nodes included an overlapped background and non-text chevrons. A separate WCAG A/AA automated pass over phone Program, Privacy, Reports and People in both themes reported no definite violations and incomplete `aria-prohibited-attr` and `color-contrast` results. Manual and broader state review remain required.

This is a partial theme and Program layout change. Feature-specific colours and the other source screens require review. The 19-screen visual and operational acceptance status remains unchanged.
