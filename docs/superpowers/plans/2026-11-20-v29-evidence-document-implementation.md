# 2.9 Evidence and documents: existing-contract implementation plan

**Status:** Implementation plan for the current authorized request, document occurrence and reuse workflows. The reference's remaining generic document lifecycle and independent supersession must be compared with existing owners before claiming full domain acceptance.

**Goal:** Use the 2.9 evidence/document layout to locate authorized prior evidence, request only unresolved material, inspect exact source versions and record independent bank review.

**Architecture:** `internal/evidence` owns requests, capture, artifacts and collection receipts; `internal/thirdparty` owns vendor assessment decisions; `internal/documentimport` owns governed imports. A source occurrence remains immutable and references the original submission/artifact. No second file store, copied answer or browser-only acceptance is introduced.

**Stack:** Go/pgx/PostgreSQL, existing object-store/inspection adapter, React/TypeScript and existing route/access registry.

## Existing API contract

These paths exist; source of precise wire definitions is `api/submitted-documents.md` and the named handler/service structs. Scope/actor fields in bodies never grant authority.

| Operation | Exact contract and observable result |
| --- | --- |
| `GET /api/v1/forms/documents` | Bounded principal-authorized inventory of submitted document occurrences; returns exact submission, field, artifact, version, digest, inspection and review metadata and continuation. No draft answer, token or storage key is returned. |
| `GET /api/v1/forms/documents/{submission_id}/{field_id}/{artifact_id}/content?response_revision_id={id}&download=true` | Exact source authorization is repeated; bytes must be `AVAILABLE` and match original digest/size before delivery. Each path segment is percent encoded. A source link does not transfer access. |
| `GET /api/v1/forms/responses/{revision_id}` | Exact immutable form response and first 100 document occurrences plus `documents_next_cursor`; owning workflow and request scope are checked before answers are returned, including scalar-only answers. |
| `POST /api/v1/vendor-assessments/{id}/prepare-request` | `{ "expected_version": <assessment version>, "audience": <address>, "deadline": <timestamp> }` → `{assessment,request,state:"PREPARED"}`. No invitation is issued by prepare. Never log the audience or a token. |
| `GET /api/v1/vendor-assessments/{id}/collection` | Current assessment/request versions, masked audience hint, deadline, fields and separate pending/accepted counts; each field has collection state and bank review state. Unknown conditional applicability remains `CONDITION_UNKNOWN`. |
| `POST /api/v1/vendor-assessments/{id}/collection/{field_id}/reconcile` | `{ "expected_version": <assessment version>, "request_id": <uuid>, "expected_request_version": <int>, "source_submission_id": <uuid>, "source_field_id": <id>, "source_artifact_id": <uuid>, "source_response_revision_id": <uuid optional>, "rationale": <text> }` → `{collection,receipt}`. Current authority and exact source access are rechecked. |
| `POST /api/v1/vendor-assessments/{id}/documents/{artifact_id}/validate` | Existing reviewer-authorized document decision; use the actual handler DTO including `field_id` where one artifact covers multiple fields. Reconciliation is collection fulfillment, not validation. |
| `GET /api/v1/evidence/requests`, `GET /api/v1/evidence/requests/{id}`, `GET /api/v1/evidence/requests/{id}/review-submission` | Principal-scoped request and exact submission reads; capture access is separate and capability-bound. |
| `POST /api/v1/evidence/requests`, `POST /api/v1/evidence/requests/{id}/submissions` | Existing request and submission contracts in `internal/evidence/model.go`; actor/tenant are bound by handler. Submission is not an evidence acceptance decision. |

The request input includes `subject_type`, `subject_id`, `title`, `purpose`, `sensitivity`, `audience_type`, `recipient`, `deadline`, `presentation`, `sections`, `fields`, optional exact form template/version and predecessor; see `CreateRequestInput` for the complete exact current schema. `CollectionResolution` records bank linkage to a previously submitted occurrence with version, source, rationale and independent review state; it does not add an answer to the respondent's map.

## Database and migration

No schema migration is required to implement the **existing** inventory, collection reuse and validation paths. Preserve the capture tables and artifact ownership; migration `000086` owns the existing collection receipt revisions. Keep `internal/evidence/collection_resolution_postgres.go` and `internal/thirdparty/assessment_collection_postgres.go` as the source of transaction and receipt behavior. Do not copy bytes to a new documents table or backfill a respondent answer. Expired, rejected, replaced or unavailable evidence invalidates current fulfillment without deleting historical receipt/decision.

For generic reference evidence-refresh and independent supersession beyond these contracts, trace exact current Program/evidence review endpoints, artifact lifecycle and source access. If they cannot represent an exact successor and accepted predecessor, define an additive migration with scoped FKs, immutable lineage, optimistic version and an atomic acceptance command before enabling the UI. This document does not invent such a migration or claim that the generic path is already available.

2. **Source anatomy.** Hash and render 2.9 `evidence.html`, `evidence-review.html`, `documents.html`, `document-workspace.html`, `document-upload.html` and their shared `assets/` at 1440/1280/1024/768/390. Map their controls, selected state, inspector and small-screen replacement to existing components, retaining real permission and availability states.
3. **UI.** Recompose `web/src/components/EvidenceWorkspace.tsx`, `components/documents/DocumentBrowser.tsx`, `DocumentFile.tsx`, `DocumentPreview.tsx`, `VendorEvidenceChecklist.tsx` and their scoped CSS. Use `documentApi.ts`, `submittedDocumentApi.ts`, `vendorCollectionApi.ts` and `evidenceRequestAdminApi.ts`; open exact source links with `encodeURIComponent`. Preserve current filter/selection on detail return and invalidate requests/selection when scope changes.
4. **Reuse flow.** Show only server-authorized source occurrences and their exact provenance/freshness. On reconcile, submit both versions and exact source IDs. Refresh on conflict; do not silently use a different version. Present collected, accepted, expired, rejected and awaiting-review separately. Keep the vendor's view limited to its authorized collection state.
5. **Artifact safety.** Route previews/downloads through existing authenticated content path and manifest verification; never embed token, audience, storage key or unrestricted source metadata in the URL, local storage, logs or search result. A scanner/storage outage yields an actionable unavailable state, not `AVAILABLE`. Preserve external invitation revocation and current source permission checks.
6. **Test and evidence.** Run from root `go test ./internal/evidence ./internal/thirdparty ./internal/documentimport ./internal/httpapi`. With an isolated migrated `TEST_DATABASE_URL`, run `go test -tags "postgres postgresintegration" ./internal/evidence ./internal/thirdparty ./internal/httpapi` and inspect skips. From `web`, run `npm test -- --run src/components/EvidenceWorkspace.test.tsx src/components/VendorEvidenceChecklist.test.tsx src/components/documents/DocumentBrowser.test.tsx src/copyQuality.test.ts`, `npm run typecheck`, `npm run check:runtime-truth` and `npm run check:ui-contracts`. Browser-test actual bytes, scope loss, keyboard, interruption and all five widths; compare reference/runtime and record named review.
7. **Deployment/rollback.** Ship compatible client against existing endpoints and schema; keep current links until route aliases have tests. Frontend rollback restores prior UI only; do not delete capture records, revoke active invitations or roll back stored review receipts. Any later schema change requires its own pre/post source-count reconciliation and forward-only history-preserving recovery plan.
